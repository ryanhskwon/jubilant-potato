jubilant-potato commands (run on the server, in the jubilant-potato folder)
==========================================================================
Read on the console: less COMMANDS.txt (q to quit), or ./serve.sh for help.
Second screen: Alt+F2 .. Alt+F6 = another console login, Alt+F1 = back.

[1] First install
git clone https://github.com/ryanhskwon/jubilant-potato.git
cd jubilant-potato
cp .env.example .env
./serve.sh key                           # makes VLLM_API_KEY, write it down
vi .env                                  # GRAFANA_ADMIN_PASSWORD
./serve.sh check                        # driver, image, transformers, models

[2] Update
git pull

[3] Start / switch / stop a model (a number from list or the full name)
./serve.sh list                          # shows numbers 1-6
./serve.sh up 2                          # = ./serve.sh up qwen3.8-27b-nvfp4
./serve.sh status
./serve.sh down

[4] Test
./serve.sh test                          # text, tool calls, images, speed

[5] Load test / capacity (TTFT, tok/s, latency, how many users)
./serve.sh loadtest                      # up to ~35 min, scan+fix sessions
./serve.sh loadtest --users 1,2 --duration 30   # quick try, ~1 min
./serve.sh loadtest --users 1,2,4,8,12,16   # 15 developers: is 16 OK?
./serve.sh loadtest --natural --users 1,4   # real wait time, model stops itself
./serve.sh loadtest --context 30000      # bigger code per session
less results/loadtest/<model>-<date>.txt # report (also a .csv)

[6] Model eval (coding task pass rate)
./serve.sh eval
./serve.sh eval --only fix-median,cart-tax
cat results/eval/summary.csv

[7] All models at once (test + loadtest + eval, takes a long time)
./serve.sh test-all
ls results/

[8] Continuous metrics collection (Grafana http://<server>:3000)
./serve.sh monitor up
./serve.sh monitor down

[9] Logs / troubleshooting
./serve.sh logs                          # Ctrl+C to stop following
./serve.sh errors                        # only error / memory / KV cache lines
./serve.sh errors | less                 # page through long output (q to quit)
nvidia-smi
docker ps

[10] OOM (out of memory) fixes - edit configs/<model>.yaml, then up again
vi configs/qwen3.8-27b-nvfp4.yaml
#   1) halve max-model-len           262144 -> 131072
#   2) gpu-memory-utilization        0.92 -> 0.95
#   3) delete the speculative-config line
#   4) halve max-num-seqs            64 -> 32
#   5) add enforce-eager: true
./serve.sh up qwen3.8-27b-nvfp4

[11] API call examples (client)
curl http://<server>:8000/v1/models -H "Authorization: Bearer <VLLM_API_KEY>"
curl http://<server>:8000/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer <VLLM_API_KEY>" -d '{"model": "qwen3.8-27b-nvfp4", "messages": [{"role": "user", "content": "Hello"}]}'

[12] Pull the image again (when check reports transformers out of range)
docker pull vllm/vllm-openai:v0.33.0

Details: docs/guide.html
